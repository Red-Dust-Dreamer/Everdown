## TL;DR(决策摘要)

1. **架构**:分阶段走"客户端单机版 → 账号云存档 → 服务器权威"三步,**最终形态为服务器权威 + 纯表现层客户端**(方案 B),部署时用方案 C(混合)过渡。
2. **多人已确认为方向**(2026-09-30),形态定为**异步聚合**:队伍成员各自挂机,伤害向服务器持有的共享 Boss 聚合(团队副本/世界 Boss),不做实时同屏。由此:**服务器权威成为团队玩法的硬前置**,客户端权威阶段只能承载展示型社交。详见 06 文档。
3. **已完成(P0)**:核心与 UI 解耦(事件输出)、RNG 全播种(可复现/可审计)、`resolve()` 懒结算(与 tick 同规则,校准偏差 ±5%)、存档 v2+迁移链。附带修复一项数值 bug(百分比主属性指数成长)。
4. **已完成(P1)**:网页版(Pyodide + xterm.js,`web/legacy/`),与 CLI 共用同一核心;NSimSun 子集字体(2:1 等宽 CJK,243KB);localStorage 存档 + 离线结算,浏览器实测通过。
5. **账号 MVP**:邮箱 + 密码(argon2id)+ JWT 双令牌,PostgreSQL。多人的数据增量(队伍/副本/贡献表)见 06 文档 §4。
6. **合规红线**:面向中国大陆公开运营需要**版号 + ICP 备案 + 实名认证 + 防沉迷**。默认海外托管,详见 02 文档第 6 节。
7. **多人前置重构(P2.5)**:`Game` 拆分为 HeroState(角色,随账号)与 BattleState(战斗会话)——纯归属重构,玩法零变化,拆分映射表见 06 文档 §3.2。

## 原则

- **CLI 版不废弃**:所有阶段保持 `python run.py` 可玩,与 Web 版共用同一个游戏核心。
- **玩法优先于基建**:没有玩家数据证明留存之前,不建账号系统(Phase 1 无账号)。
- **不信任客户端**:从第一天起,所有"数值正确性"相关的代码路径按"客户端可能是假的"来设计;多人共享状态(Boss 血量/贡献)一律服务器持有。
