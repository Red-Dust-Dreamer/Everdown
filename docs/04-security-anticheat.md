# 04 · 安全与防作弊

> 原则:客户端可能是伪造的。A 形态阶段(客户端权威)只做"廉价校验 + 审计留痕",不追求杜绝;B 形态阶段由服务器权威天然免疫大部分作弊。本文同时覆盖账号侧通用安全。

## 1. 作弊面分析(本游戏)

| 资产 | A 形态风险 | B 形态残余风险 |
|------|-----------|----------------|
| 金币/重铸石 | 改内存后上传存档 | 无(服务器结算与扣费) |
| 装备/词缀 | 伪造神装 JSON | 无(掉落由服务器 roll) |
| 区域进度 | 篡改 zone 直达高层 | 无 |
| 时间(挂机收益) | 改本地时钟/直接伪造 last_saved | 无(服务器时间为唯一时钟) |
| 排行榜 | 全部不可信 | 可信 |

结论:**排行榜上线(Phase 3)必须与服务器权威结算同批交付**,否则榜单无意义。

## 2. 包络校验(A 形态的廉价防线)

PUT /save 时对上传存档做"理论可达性"检查,不通过则拒绝(400)并记审计:

```
给定 playtime_validated(服务器累计收到该角色的已结算时长):
1. 等级上限:以最快理论升级曲线 xp_req 增长(BAL['xp_req_growth'])反推 max_level(playtime);
2. 区域上限:每层最少 kills_per_stage 杀 × 理论最快击杀时间 → max_zone(playtime);
3. 金币上限:最高效刷金速率 × playtime × 裕度系数 3;
4. 装备词缀上限:每词缀值 ≤ 其基值上限 × item_main_g^tier × 稀有度倍率 × 强化倍率(×1.2 容差);
5. 强化等级:plus × 费用累计 ≤ 金币累计收入。
```

- 裕度统一放宽(个人项目避免误杀,宁可漏抓);
- CLI 玩家导入存档走同一检查;CLI `--sim` 跑出的极限数据可作为包络标定参考;
- 拒绝不是封号:提示"存档异常,请联系/重新开始",记 `audit_log`。

## 3. 速率限制(全阶段)

| 范围 | 规则 | 响应 |
|------|------|------|
| /auth/register | 5/IP/小时 + 1/邮箱 | 429 |
| /auth/login | 5/账号/15分钟,20/IP/小时 | 429 + 锁定递增 |
| /auth/password/forgot | 3/邮箱/小时 | 200(防枚举) |
| PUT /save | 1/角色/10秒(客户端本来 30s 自动存) | 429 |
| /action | 10/角色/秒(人类手速上限) | 429 |
| GET /state | 60/角色/分钟 | 429 |

实现:进程内存令牌桶起步;多实例后迁 Redis(`INCR` + `EXPIRE`)。429 带 `Retry-After`。

## 4. 服务器侧通用安全

- **时间源**:一律 `server_time`(NTP 同步的主机时钟);`last_resolved_at` 与请求时间倒挂 → 拒绝并记审计;
- **结算上限**:单次 resolve 的 elapsed 封顶 = `offline_cap_sec`(12h,复用现有 BAL 常量),超出部分丢弃——防"改时间戳白嫖";
- **输入校验**:Pydantic schema 严格白名单;存档 JSON 深度/大小限制(≤ 256KB,背包 40 件 × 词缀 6 条远小于此);
- **升级包大小**:装备对象只接受已知字段,未知字段剥离(防注入 JSONB 垃圾);
- **传输**:全站 HTTPS(Cloudflare/Fly 自动),HSTS;
- **依赖**:pip-audit 进 CI;FastAPI 关 debug;错误响应不回溯栈;
- **注入面**:无动态 SQL(全 ORM/参数化);CLI 导入的存档文件同样按 schema 校验。

## 5. 账号安全(摘要,细节见 02)

- argon2id 密码哈希;登录防枚举(账号不存在与密码错误同响应);
- refresh token 哈希存库、旋转使用、可吊销;
- 敏感操作(改邮箱/注销)二次验证密码;
- IP/UA 变化邮件提醒(Phase 3 可选)。

## 6. 滥用与内容

- display_name:长度 1-16,拒绝空白/控制字符;不做敏感词(成本高),提供举报+手动处理;
- 单账号角色数 MVP=1,注册门槛足以限制刷榜(配合邮箱)。

## 7. 事件响应预案

| 事件 | 动作 |
|------|------|
| 单角色存档异常 | 拒绝 + 审计;同角色 3 次 → 冻结存档写入,人工看审计 |
| 账号批量注册(>20/IP/日) | IP 段限流 + 邮箱验证强制开启 |
| 漏洞利用刷金并被上传排行榜 | 下榜 + 回滚该角色至最近正常快照(audit_log 里每次 save 都有 summary,可回放) |
| 数据泄露 | 通知用户 + 全量强制重置 refresh token(密码哈希若泄漏,argon2id + 强制改密) |
