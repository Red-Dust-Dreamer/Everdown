## 数值体系 2.0(✅ 2026-09-30)

应设计方向调整(不要指数增长、成型久、数值小),全套平衡从指数改为多项式/线性:

| 项 | 旧(指数) | 新(多项式) |
|----|-----------|-------------|
| 怪物 HP | 50×1.145^t | 50 + 26×t^1.28 |
| 怪物攻击/防御 | 1.08^t / 1.10^t | 6.8+2.2×t^1.05 / 3+1.5×t |
| 装备主属性 | 5×1.16^t | 基值 + 槽斜率×t^1.12(**幂刻意低于怪物**,推进随深度减速) |
| 数值词缀 | u(lo,hi)×1.15^t | u(lo,hi) + 线性小步长×t |
| 金币/经验 | 1.105^t / 1.10^t | 6+3×t^0.85 / 9+5×t^0.9 |
| 升级需求 | 60×1.25^lv | 60×lv^1.65 |
| 强化费用 | ×1.30^plus(指数) | (25+1.8t)×(1+0.5p+0.04p²) |
| 强化收益 | +8%/级 无限 | **分段递减**:0-10级+8%、11-20级+4%、21级起+2% |
| 技能费用 | 100×1.5^lv×1.1^t | 60+35lv+**6lv²**+2t(平方收敛) |
| 头目攻速 | 同普通怪 | ×2 间隔(蓄力重击,开局可磨) |

实测(autopilot 挂机):60 分钟 Lv76/76 区/DPS 2.5万/金币 2-3 万;4 小时 Lv250/390 区/DPS 23万,后期死亡回升(真实卡墙出现)。存档 bump v3(新增 stat_mods;旧档数值量级不匹配,建议重开)。

**特殊属性扩展口**:新增 `Game.stat_mods` + `add_stat_mod()/remove_stat_mod()`——任何渠道挂属性
(`add`/`pct`),统一在 `recalc_hero` 应用、随档持久化;成就已迁入同一管道(`achievement_mods`)
作为示范用法。未来属性丹/悬赏属性奖励/公会 buff 零核心改动即可接入。

resolve 校准现状:与纯挂机 tick 对照,单点公式偏差 ~12%,5 分钟窗口均值 -6.5%(±30% 方差
来自装备随机流分叉);**对高战吼/高技能 build 存在 -30%+ 系统性悲观**(技能期望折算的
build 依赖),已识别,P3 服务器权威落地前需精细化(按技能循环离散模拟或引入校正因子)。

## P0:核心抽离(✅ 已完成,2026-09-30)

原定四项交付与实际落地:

1. **事件化输出 ✅**:`Game` 不再持有任何 UI 状态;日志/飘字/toast/动画经 `emit()` 进入 `events` 队列,由宿主消费——CLI 挂 `abyss/view.py`(View 类),网页宿主 `web/legacy/abyss_bridge.py` 同样只 drain 事件;
2. **RNG 播种 ✅**:角色创建生成 seed(随存档 v2 保存),combat/items/systems 全部掷点走 `g.rng`;`--sim` 同 seed 两次运行逐行一致;
3. **结算函数化 ✅**:`systems.resolve(state, elapsed)` 替代原 `compute_offline` 估算,与逐 tick 战斗共用同一套状态迁移(advance/retreat/gain_xp/add_item/quest_progress);刀级随机保留(`_roll_knives`,修正连续近似的临界刀数低估),校准偏差 ±5% 内;CLI 离线结算与未来服务器结算共用此函数;
4. **存档版本纪律 ✅**:v2(新增 seed)+ `migrate_save` 迁移链。

与原计划的偏差(有意):未迁移到独立 `core/` 目录——核心文件留在 `abyss/` 内以保持 CLI 零改动;目录级拆分推迟到 P2.5(Hero/World 分离时一并处理)。

**验收结果**:demo 全过、7 页渲染 30×100 精确、按键冒烟全过、同 seed sim 可复现、resolve 校准 ±5%、离线端到端流程通过。附带发现并修复一项数值 bug:项链/戒指的百分比主属性(暴伤/暴击)此前误吃指数成长(暴伤可达 10⁷%),现改为固定基值 × 稀有度倍率;修复后 60 分钟模拟曲线更健康(18 区 / DPS 5×10⁹)。

## P1:网页单机版(✅ 已完成,2026-09-30,Pyodide + xterm.js)

实际落地内容:
- `web/legacy/`:index.html + main.js + `abyss_bridge.py`(网页宿主,boot/tick/key/frame/save/import);
- 核心 10 个模块写入 Pyodide 虚拟 FS 加载,游戏逻辑零改动;
- **本地 vendor** Pyodide 0.26.4 + xterm 5.5(`web/legacy/vendor/`,约 13MB)——当前网络环境下 CDN(pyunpkg 慢/其余被墙)体验差,本地化后 **10 秒内加载且完全离线可玩**;vendor 缺失时自动回退 CDN;
- **字体**:`web/tools/build_font.py` 从系统 NSimSun(真 2:1 等宽 CJK)子集化出 243KB woff2,覆盖游戏全部字符——xterm.js 网格对齐的关键;换字体须保持全角=2×半角;
- 存档:localStorage(键 `abyss_save_v2`),10 秒自动保存 + 页面隐藏/关闭时保存;支持导出/导入 JSON(CLI 的 save.json 可直接导入);重开页面自动离线结算(复用 resolve,浏览器实测:1 分钟离开 → 32 杀/7 件掉落精确结算)。

浏览器实测通过:加载、战斗渲染(无乱码/对齐良好)、按键切页、存档往返、离线弹窗、帮助弹窗。

运行:`py -m http.server`(仓库根),访问 `http://localhost:<port>/web/legacy/`(file:// 打开不可用,Pyodide 需 http)。

## P2:账号 + 云存档(A 形态)

- `server/`:FastAPI + SQLModel;接口仅 02 文档的 /auth/* + 03 文档的 /save;
- DB:Neon(Postgres 免费档);邮件:Resend 免费档;
- 前端(P1 页面扩展):登录/注册/找回页;启动时"本地 vs 云"对比(`updated_at` 新者胜,提示覆盖);
- CLI 存档导入:网页上传 save.json → 包络校验 → 入库;
- 部署:Fly.io single machine(免费额度内)+ Cloudflare;
- 运维:每日自动备份(Neon 自带 PITR),`/healthz` 探活,UptimeRobot 监控。

验收:两台设备登录同一账号进度一致;误删 localStorage 后可恢复。

## P3:服务器权威 + 排行榜(B 形态)

- 落地 01 文档 §4 的 `resolve/apply_action/simulate_view` 三函数(吃 P0 的 StateCore);
- 新客户端(DOM 网格版)起步:`render.py` 的布局逻辑翻译为 CSS Grid 组件树,轮询 30s + 操作即同步;旧 xterm.js 版退居"怀旧模式"(改走 WebSocket 推流或仅本地演出);
- 排行榜:最深区域/装备评分/击杀数三个 ZSET;
- 包络校验从"防线"降级为"审计参考";
- 压测:1 万角色 × 平均 30s 一次 /state,解析结算 < 10ms/次,单 small 实例 + Redis 可承载。

验收:断网 12 小时后 reconnect,服务器结算与本地预期偏差 < 1%;改包/改时间作弊无效。

## 决策点回顾(何时触发下一阶段)

- P1 → P2:**有人在玩**。参考阈值:月独立访客 > 500 或收到"想多设备同步"诉求;
- P2 → P2.5 → P3:**确定做多人**(已确认,2026-09-30)或 出现公开改档/排行榜有人刷;

- M1 → M2:**真实需求**——只有玩家主动要"一起在线打"才做实时房间,否则永远停在异步聚合;
